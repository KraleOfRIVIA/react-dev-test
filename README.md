# Тестовое задание Frontend разработчик на React.

Вам дан проект Дашборда со списком звонков, для операторов, в котором они могут просматривать детали звонка и менять их статусы.

```
Проект уже работает, но в нем намеренно допущены ошибки, которые вам предстоит выявить и исправить.
```

## Что нужно сделать:

- Найти и исправить ошибки в коде
- Правильно обработать ошибки от API
- Улучшить качество и читаемость кода

## На что стоит обратить внимание:

- Что может вызывать проблемы с производительностью
- Работа с React Query и обработка ошибок
- Работа с состоянием
- Типизация

## Чего делать не нужно:

- Полностью рефакторить код
- Тратить время на стилизацию

## Как отправить свое задание на проверку:

- Форкнуть репозиторий на GitHub
- Внести изменения в master ветке
- Описать в README какие баги и недочеты вы обнаружили, исправили и почему
- Отправить ссылку на репозиторий в GitHub

## Исправленные баги и недочеты

1. `useMutation` был подключен с некорректным контрактом (`mutationFn` ожидал `(id, status)`, а `mutate` вызывался объектом). Исправлено через типизированный payload `{ id, status }` и адаптер в `mutationFn`.
2. В optimistic update и rollback использовались `any` и небезопасные обращения. Добавлена строгая типизация данных кэша, контекста отката и безопасные проверки на отсутствие данных.
3. В списке звонков не было обработки `error` и `empty` состояний, а также использовался non-null assertion (`data!`). Добавлены явные состояния `loading/error/empty`.
4. В карточке звонка состояние хранилось как целый объект в Zustand, что приводило к устаревшим данным после сокета/мутаций. Хранение заменено на `selectedCallId`, а текущий звонок вычисляется из React Query кэша.
5. Кнопка смены статуса не показывала прогресс и ошибки API. Добавлены `pending`-состояние, отключение кнопки на время запроса и отображение ошибки мутации.
6. Socket-подписки имели утечки: `subscribe` не отписывал слушателя, `connectSocket` не имел cleanup и мог создавать дубли интервалов. Добавлены корректные `unsubscribe`/`disconnect` и безопасный жизненный цикл соединения.
7. Socket-обновление заменяло весь объект звонка частичным payload, теряя поля. Исправлено на merge: `{ ...call, ...update }`.
8. `useSocket` не был подключен к экрану дашборда. Хук подключен в корневом компоненте страницы.
9. Для длинного списка снижены лишние ререндеры: `CallItem` мемоизирован, пропсы стабилизированы.
10. Закрыты lint-замечания (`prefer-const`, зависимости эффекта, удаление `any`).

Эти изменения сохраняют текущую структуру проекта, но устраняют ошибки поведения, улучшают обработку API-ошибок, типизацию и производительность.
